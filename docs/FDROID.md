# F-Droid Readiness

This project is intentionally configured for F-Droid's source-build model.

## Inclusion-policy choices

- MIT-licensed source and original assets.
- Only free/open-source runtime dependencies.
- No ads, analytics, trackers, proprietary SDKs, Firebase, account service, push service, or binary blobs.
- No remote code loading or Expo Updates.
- Android Internet permission is blocked and checked in CI.
- The application works offline after installation.
- Store metadata is maintained in Fastlane format.
- The package name uses the controlled GitHub namespace: `io.github.zengtao227.fortunetelling`.

## Proposed fdroiddata metadata

The file `fdroid/io.github.zengtao227.fortunetelling.yml` is a starting point for the fdroiddata merge request. Before submission:

1. Replace `commit` and `CurrentVersionCode` values if a later release is tagged.
2. Confirm the tagged source archive contains the dependency lock generated by Node 22.13/npm 11.5.
3. Run `fdroid scanner` against the source and generated APK.
4. Build in a clean Debian/Ubuntu VM without Expo/EAS credentials.
5. Test the unsigned APK on a physical Android device.
6. Create a signed upstream release tag, although F-Droid will sign its own build.

## Reproducible builds

Basic F-Droid inclusion requires that F-Droid can build the app from source. Byte-for-byte reproducible builds are a stronger optional goal. Achieving that status also requires pinning the complete npm dependency graph, Gradle/JDK/Android SDK versions, timestamps, and native build inputs, then comparing clean-build APKs.
